Section 1

Introduction

Purpose, scope, definitions, and an overview of this specification document.

1.1Purpose

This Software Requirements Specification (SRS) defines the complete set of requirements for the Sikkim Tourism & Civil Aviation Department AI Assistant (hereafter "STAC Assistant" or "the System"). It serves as the authoritative reference for design, development, testing, and maintenance activities.

This document is intended for the development team, the Department of Tourism & Civil Aviation (Government of Sikkim), project supervisors, and any future maintainers of the System.

1.2Scope

The STAC Assistant is a full-stack web application that provides an AI-powered conversational interface for tourists, travel planners, and the general public to obtain accurate, real-time information about travel destinations, permits, routes, accommodation, festivals, and all aspects of visiting Sikkim.

The System encompasses:

  • ✓Real-time RAG Chatbot — Retrieval-Augmented Generation using LangChain + Qdrant + Google Gemini Embeddings + Groq LLM (llama-3.3-70b-versatile), streamed via Server-Sent Events (SSE).
  • ✓Destination Explorer — A searchable, filterable catalogue of Sikkim's key destinations with full detail views, permit information, and travel tips.
  • ✓Admin Sync Endpoint — Protected endpoint for re-indexing the vector store without server restart.
  • ✓Dual Database Mode — Mock in-memory data for development; MySQL for production deployment.

Section 2

Overall Description

Product perspective, key functions, user classes, operating environment, and constraints.

2.1Product Perspective

The STAC Assistant is a new, self-contained system built as a Summer Internship Project for the Tourism & Civil Aviation Department, Government of Sikkim. It replaces manual tourist inquiry handling with an intelligent conversational interface accessible via any modern web browser.

It is architecturally independent — it does not integrate with any existing GoS IT infrastructure — but is designed to be portable and deployable on any cloud or on-premise Linux server.

ℹ️
Zero External Services in Dev Mode — Qdrant runs fully in-memory and the database falls back to rich mock data, enabling complete offline development with only API keys required.

2.5Design & Implementation Constraints
  • ⚠Gemini API Key Required — Google Gemini is used exclusively for text embeddings (models/gemini-embedding-001). No embedding fallback exists. The key must be set before startup.
  • ⚠Groq API Key Required for Chat — The LLM inference step uses Groq (llama-3.3-70b-versatile). Without this key, the chat endpoint returns a user-visible error, not a system crash.
  • ⚠Embedding Model Dimension Detection — The Qdrant collection vector size is auto-detected at runtime by embedding a probe string; this adds ~500ms to first startup but prevents dimension mismatch errors.
  • ⚠No Virtual Environments on Replit — Dependencies are managed via requirements.txt and the host Python environment.
  • ⚠Deprecated Embedding Model — text-embedding-004 has been superseded by Google in favour of newer embedding models; the system uses models/gemini-embedding-001 (3072 dims by default).
2.6Assumptions & Dependencies
  • ✓Stable internet connectivity to Gemini and Groq APIs is assumed in production.
  • ✓For production MySQL mode, a MySQL 8+ instance with the schema from docs/schema.sql is assumed to be provisioned.
  • ✓The ALLOWED_ORIGINS environment variable is set to the exact production frontend URL before go-live.
  • ✓An ADMIN_API_KEY of at least 32 random bytes is set before enabling the admin sync endpoint in production.

5.3Reliability & Availability
  • ✓Non-fatal startup failure — If Qdrant population fails at startup, the server still starts and falls back to basic keyword search. The error is logged with full traceback.
  • ✓Graceful LLM error handling — If the Groq API fails mid-stream, a user-friendly error message is yielded instead of crashing the connection or exposing raw Python exceptions.
  • ✓Missing API key messages — Missing Groq/Gemini keys yield a clear error message to the user (not a 500 server error).
  • ✓Target uptime — 99.5% for production deployment, subject to third-party API availability (Gemini, Groq).
5.4Maintainability
  • ✓Repository pattern — BaseRepository abstract class decouples business logic from data source. Switching from mock to MySQL requires only changing USE_MOCK_DB=false.
  • ✓Configuration centralisation — All settings are in app/config.py via Pydantic Settings, with full validation and documented defaults.
  • ✓Embedding dimension auto-detection — Changing the embedding model requires only updating GEMINI_EMBEDDING_MODEL; no code changes needed.
  • ✓LangChain LCEL chains — The RAG pipeline is composable and each step (rephraser, retriever, answerer, suggestions) is independently testable.
5.5Scalability
  • ✓Horizontal scaling — The backend is stateless (sessions stored in DB). Multiple Uvicorn instances can run behind a load balancer with a shared MySQL instance.
  • ✓Qdrant Cloud migration — Setting QDRANT_URL migrates from in-memory to a persistent, scalable Qdrant Cloud cluster with zero code changes.
  • ✓Async I/O — All database and external API calls are async (Python asyncio), allowing high concurrency without thread blocking.

6.1RAG Pipeline Data Flow

When a user sends a message, the following sequence executes:

  1. User message is sanitised (strip whitespace, NFKC normalise, log injection patterns).
  2. Message is persisted to the data store as a user message.
  3. Full conversation history is loaded. A rephrasing sub-chain (Groq) rewrites the latest question as a self-contained search query.
  4. The self-contained query is embedded using Google Gemini (models/gemini-embedding-001, 3072 dims).
  5. Qdrant performs a similarity search against the sikkim_destinations collection, returning the top-k most relevant documents.
  6. Retrieved documents are formatted and injected as context into the system prompt.
  7. The answer chain (Groq Llama 3.3 70B) streams token-by-token via SSE to the browser.
  8. After the stream completes, the follow-up suggestion chain generates 3 short questions and sends them as a final suggestions event.
  9. The complete assistant response is persisted to the data store.

Section 9

Security Design

Defence-in-depth security measures implemented across all layers.

🛡️

Security Headers Middleware

Custom SecurityHeadersMiddleware appended to every response: X-Content-Type-Options, X-Frame-Options: DENY, X-XSS-Protection, Referrer-Policy, Permissions-Policy, and HSTS in production.

⏱️

SlowAPI Rate Limiting

Chat endpoint limited to 30 requests/minute per IP using slowapi. Exceeding this returns HTTP 429 Too Many Requests.

🔐

Admin Key Authentication

The admin sync endpoint uses X-Admin-Key header validation via FastAPI Depends. Fail-closed: empty key = all requests denied.

🌐

CORS Hardening

Restricted to explicit origins via ALLOWED_ORIGINS. Methods and headers are also allowlisted. Wildcard * is logged as a security warning.

🧹

Input Sanitisation

User messages are stripped, NFKC-normalised (prevents homograph attacks), and scanned for 8 injection pattern regexes. Pydantic v2 validates all request bodies.

🆔

UUID Validation

All conversation ID path parameters are validated as proper UUIDs before any database query, preventing path traversal and format-injection attacks.

Section 13

Appendix & Glossary

Extended glossary of technical terms and project-specific concepts.

AExtended Glossary
Term Full Form / Explanation
ASGI Asynchronous Server Gateway Interface — The Python web server standard that enables async I/O in FastAPI and Uvicorn.
Embedding A fixed-dimension dense vector representation of text that encodes semantic meaning. Similar texts have similar vectors.
Cosine Similarity The metric Qdrant uses to rank retrieved documents — measures the angle between two embedding vectors.
Vector Store A specialised database optimised for ANN (Approximate Nearest Neighbour) search over high-dimensional embedding vectors.
LCEL LangChain Expression Language — Functional chain composition using | pipe syntax, enabling declarative RAG pipelines.
Groq An AI inference provider offering ultra-fast LLM inference using custom LPU (Language Processing Unit) hardware.
Hallucination When an LLM generates plausible-sounding but factually incorrect content. RAG mitigates this by grounding answers in retrieved facts.
Lifespan FastAPI's startup/shutdown context manager — used here to populate the Qdrant vector store before the first request is served.
Pydantic v2 Python data validation library used for all request/response schema validation and settings management.
Uvicorn High-performance ASGI web server used to run the FastAPI application.
SSE Server-Sent Events — A one-way HTTP push protocol where the server streams data: ...\n\n events to the client.
HMR Hot Module Replacement — Vite's feature that updates the browser without a full page reload during development.
MMR Maximal Marginal Relevance — A retrieval strategy that balances relevance with diversity in retrieved documents.
Permit (ILP/PAP) Inner Line Permit / Protected Area Permit — Government-mandated entry permits for restricted zones in Sikkim, including border areas like Nathu La and North Sikkim valleys.
